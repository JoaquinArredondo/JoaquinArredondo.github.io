The Design Problem

Model the interaction as changing state, not purchasing progress.

The research started from a critique of affinity meters and fixed romance thresholds. The prototype instead separates what the player did, how that action affects the NPC now, what the relationship means, and which response currently has the strongest utility.

Immediate State

PAD

Pleasure, Arousal, and Dominance store continuous affect that can move incrementally after each interaction.

Semantic Layer

Intent

Forty-six authored player actions map into nine reusable intent categories so the state model can be tuned without duplicating every rule.

Decision Layer

Utility AI

Candidate responses score PAD, recent emotional change, intent context, authored curves, weights, and a bounded personality bias.

System Architecture

Human-readable interaction enters a computational decision pipeline.

The implementation status is part of the story. The decision core works as a prototype; relationship wiring, personality data quality, and final response expression were not equally complete in the handoff snapshot.

Action + Intent Authoring

Response behavior is data, not a hard-coded branching tree.

Emotional response assets collect their considerations, response curve, weight, optional animation trigger, cooldown, and personality bias in ScriptableObjects. That makes the decision layer inspectable in Unity instead of burying tuning inside one controller script.

RESPONSE ASSET

One response can combine several pieces of evidence.

This action asset references low Pleasure, low Arousal, and high Dominance considerations, then exposes its curve and personality-bias settings for tuning.

COMPOSABLE AUTHORING

State and recent change can both affect the same decision.

The Anchor asset combines current PAD state with a recent positive Pleasure delta, then applies a bounded personality preference after situational scoring.

Emotional State

PAD is treated as continuous runtime state; labels remain a readable summary.

Pleasure, Arousal, and Dominance are normalized values. The system also stores the most recent delta so candidate actions can respond to both the current state and the direction of the latest change.

Utility AI Decision Layer

Small authoring components build up to a complete response score.

The decision layer is deliberately decomposed. Considerations define how state becomes evidence, the Emotion Brain owns the candidate set, and the NPC Controller chooses between ordinary and emotional decision paths.

CONSIDERATION

Curves turn state into tunable desirability.

A consideration can read one PAD axis and map it through an authored curve instead of relying on a binary rule.

CANDIDATE SET

The brain evaluates authored response assets rather than one fixed branch.

The handoff snapshot assigns 46 emotional actions to each demo NPC brain, allowing the scoring layer to rank a broad response vocabulary.

NPC CONTROLLER

Emotional decisions sit inside a broader NPC state machine.

The controller coordinates movement and emotional-trigger timing so the research system can coexist with the prototype's ordinary needs-based behavior.

Preliminary Validation

The paper tests the architecture with the same interaction sequence across two configured NPC profiles.

The research paper reports a controlled A/B simulation beginning from identical PAD state and applying the same three player actions—TeaseHarsh → Apology → Promise. The two configured profiles produced different PAD trajectories and, in some steps, different selected responses.

01 · ConflictTeaseHarsh

Both agents move toward a negative, high-arousal state.

02 · RepairApology

Recovery differs between the two configured profiles.

03 · SecurityPromise

Both continue recovering while retaining different PAD values.

InterpretationDivergence

The paper uses the run as preliminary system-level evidence that weighting can change trajectories and selection.

Important limitation

This was a system-level simulation, not a player study of emotional realism. The later technical handoff also audits the Unity snapshot and identifies personality-asset/schema problems that should be fixed before stronger behavioral claims are made.

Implementation Truth

The most useful result is a working decision foundation—and a precise map of what still needed work.

Implemented

Decision Core

Player-action taxonomy, action-to-intent mapping, per-action intensity, PAD state and deltas, utility considerations, response curves, emotional action scoring, and personality-bias code are present in the prototype.

Partial / Prototype

Relationship + Personality

The relationship model exists in code but was not wired into the inspected scenes. Personality bias code exists, while much of the serialized profile content required cleanup and migration.

Not Fully Implemented

Expression + Persistence

Selected responses mostly resolve to logging/cooldown scaffolding. Production dialogue, embodied response animation, memory, consent/boundary appraisal, and durable relationship persistence remained future work.

Research framing

PAD, Sternberg-style relationship dimensions, and NERIS/MBTI-inspired personality parameters are used as computational and authoring abstractions. The project does not claim to reproduce human emotion, diagnose personality, or prove perceived romantic realism.
